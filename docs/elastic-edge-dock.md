# 弹性边缘收纳（候选）

向任意方向拖动 Notch，抓取点二维 1:1 跟随鼠标，尾端连接在屏幕边缘并逐渐拉长、变细；松手后继承双轴速度，再回弹到边缘。悬停只探出一点，再拉一次恢复当前任务。

当前实现支持既有的右屏幕边缘。它不是任意位置的桌面窗口拖动，不改变会话状态或任务结果。

## 实现

- `EdgeDockModel` 保存本体位置、尺寸、收纳进度、双轴释放速度和弹簧状态。位置采用欠阻尼弹簧，尺寸采用临界阻尼；回位时可轻微越过垂直终点，接触屏幕边缘时压缩本体。
- `EdgePanGesture` 使用 4 pt 的二维距离判断拖动意图，不锁轴。坐标来自同一个鼠标事件并换算到屏幕，避免窗口本身变宽时反馈到拖动距离；原生文字编辑区保留选择行为。
- `EdgeDockGeometry` 统一计算本体、弯曲连接和窗口边界。`EdgeDockController` 保持边缘锚点，窗口包住实时轮廓；收纳为 6×28 pt、2 pt 圆角的窄矩形，悬停为 12×28 pt。AppKit 外层及玻璃内容层的大圆角在此时关闭，避免二次裁切。
- 原有 AppKit 尺寸动画在拖拽开始时停止，避免旧展开动画继续覆盖鼠标驱动的尺寸。展开内容在收纳完成后才折叠。
- 机器人及任务视图保持同一个实例；隐藏时暂停待机及时间线绘制，任务数据继续更新。恢复时使用最新状态和尺寸。
- 正式入口记住手动收纳偏好。减少动态效果时，直接跟手，释放后立即到终点。右键和可访问性操作也能恢复。

## 验证记录 · 2026-09-21

- `npm test`：59/59 通过。
- `npm run test:edge-dock`：八方向抓取点、双轴速度继承、释放无位置跳变、反向打断、恢复时任务尺寸变化、悬停端点、减少动态效果、真实窗口收纳范围通过。
- 第一轮回归重现了“开始拖动后旧 AppKit 展开动画仍在改尺寸”，修复后通过。
- `npm run test:geometry`：原有展开、快速悬停、多灯高度、长内容高度通过。
- `npm run test:presentation`：反向机器人转场、准确端点、乱序响应及 40 次状态切换回放通过。
- Codex 原生鼠标操作：待机与运行状态拉走/拉回、展开问题拉走/拉回、问题仍可单击提交、本地问答提交检查通过。
- 隐藏期间收到新问题仍保持隐藏；恢复后可继续处理。从选项上开始拖动不会误提交答案。
- 悬停的 6→12 pt 弹簧及准确端点通过模型回归；自动操作接口未产生真实悬停事件，鼠标停留的实际手感留给独立预览试用。

这些检查使用本地模拟状态，未调用 DSH 模型。正式 DSH.app 尚未安装这个候选。独立预览见 [运行说明](../tools/elastic-preview/README.md)；实际手感由预览试用确认。

二维修订另生成了六个原生轮廓样本和 60 帧回弹序列；水平初始位置 140 pt 的快速斜甩先继续至约 145.6 pt，再回到边缘；垂直方向越过终点约 8.2 pt 后收敛。小凸起的直边、2 pt 圆角和两层原生裁切均单独检查。
