# 官方桌面版 0.1.7-rc.2 适配

本分支保留 `ff78f13` 的完整弹性拖拽、左端变细、隐藏贴边和关注事件弹回，合入 `e79bbf1` 的 RC2 兼容分支，并保存当前本地桌面部署已经采用的 Home 路径、原生辅助程序托管、后台子任务及桌面唤起适配。

## 本次故障

正式 Host 给辅助程序传入 `DSH_NOTCH_RUNTIME_FILE`，用于指定连接文件。旧原生入口却用同一个变量判断“演示”，把窗口向内移动 360 pt，并让决策面板忽略自动折叠。现在连接选择与显示行为完全分开：正式入口始终以物理屏幕右边缘为锚点，离线演示只走已有显式入口。

## 验证

- `npm run test:desktop-launch` 使用真正的 `AppDelegate` 和离线连接文件，检查原生窗口边界：旧入口测得 360 pt 间隙，修复后为 0 pt。测试不连接真实 Host，不调用模型。
- `npm run test:edge-dock` 通过，覆盖二维拖动、连续形变、原形裁切、回弹打断、重要事件恢复和减少动态效果。
- `npm test`：61/61 通过，包含 RC2 的 `jobs.list(agent.id)`、`job.owner` 和主任务归属。每个测试进程使用临时 `DSH_HOME`，防止继承真实 Home 写入已读状态。
- Release 原生构建与 Host 预编译构建通过；`dshx check` 检查源入口通过，热替换文件集合同时声明实际加载的 `lib/index.mjs` 与源码及辅助模块。
- 原生预览实操完成斜向拖动收纳、运行更新保持隐藏、完成后完整弹回。

## 部署边界

本次运行中需要改变的只有用户目录里的原生辅助程序。当前 Host 已经加载 RC2 适配的 Host 插件，服务器部分不需要再激活。更新采用辅助程序自己的短更新租约、哈希与进程身份检查、备份和原子替换；由现有托管器拉起唯一新辅助进程。官方应用包、Host 进程、profile 配置及真实任务均不修改。

当前 DSHX 外部 CLI 的 desktop `activation-plan` 能分类为 artifact，但离线 profile 合成需要 Creator+ 发出的短时能力，返回 `DESKTOP_PROFILE_BRIDGE_REQUIRED`。本次不绕过此限制、不伪造票据、不执行 Host 插件激活；原生辅助程序的独立更新与运行验证单独记录。以后若改 Host 模块，仍需满足对应激活流程。

正式验收区分源代码、构建、安装哈希、唯一进程、Host 快照和 GUI 操作。独立预览不等于向正式会话注入事件，算法测试不等于实屏帧率保证。
