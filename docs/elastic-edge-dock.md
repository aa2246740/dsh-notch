# 弹性边缘收纳（候选）

向任意方向拖动 Notch，短距离二维 1:1 跟随鼠标，远距离阻力渐强。右端贴住屏幕，外壳向抓住的左端连续收窄；拉得越远，左端本身和里面的内容一起变细。松手后继承双轴速度，再回弹到边缘。收纳终点是将恢复原形的外壳平移进屏幕，留下左侧的一小截。悬停只改变露出的多少，再拉一次恢复当前任务。

当前实现支持既有的右屏幕边缘。它不是任意位置的桌面窗口拖动，不改变会话状态或任务结果。

## 实现

- `EdgeDockModel` 保存外壳位置、尺寸、收纳进度、双轴释放速度和弹簧状态。回位时可轻微越过垂直终点；向屏幕内收纳的阻尼更大，保持残留部分可见。收纳和探出只做平移，不压缩宽高。
- `EdgePanGesture` 使用 4 pt 的二维距离判断拖动意图，不锁轴。坐标来自同一个鼠标事件并换算到屏幕，避免窗口本身变宽时反馈到拖动距离；原生文字编辑区保留选择行为。
- 手势识别器暂存主鼠标按键事件；普通单击在判定不是拖动后正常交给按钮，已识别的拖动不再把松手交给选项或审批。内容在拖动时同时禁用，避免已开始的按钮跟踪误触。
- `EdgeDockGeometry` 使用 RootView 同款的 16 pt 连续圆角。拉伸先取原外壳与完整边缘接触面的单一凸包，再从固定端到抓取端连续收窄；离开边缘的自由端也逐渐形成圆角。左端不会保留一个原厚度的头部。轮廓沿张力展开，内容使用同一形变。
- 收纳保留抓取时的原外壳高度，左侧露出 8 pt，悬停露出 14 pt。端点直接使用原始连续圆角的平移裁切。后台任务更新不会改变残留部分的形状，恢复时采用最新任务尺寸。AppKit 外层及玻璃内容层的额外圆角关闭，避免对这一小截二次裁切。
- 原有 AppKit 尺寸动画在拖拽开始时停止，避免旧展开动画继续覆盖鼠标驱动的尺寸。展开内容在收纳完成后才折叠。
- 机器人及任务视图保持同一个实例和逻辑排版尺寸。拖动时，原生图层将内容和局部裁切沿拉力的垂直方向压缩，压缩比例与左端外壳相同，回位后恢复原形。逐帧位移、形变和透明度不发布给 SwiftUI，避免每帧重新排版。隐藏时暂停待机及时间线绘制，任务数据继续更新。
- 状态更新使用窗口的 `CADisplayLink`，目标 60 Hz。拖动时提前预留能容纳轨迹与速度余量的画布，飞行中窗口尺寸保持不变；结束后才缩回真实命中区域。
- 外壳宽高不变的回弹，以解析弹簧按 120 Hz 生成候选采样，再合并误差预算内的尾段样本，一次提交到 Core Animation。轮廓、内容位移、透明度与局部裁切使用完全一致的采样时刻，避免主线程偶发阻塞打断回弹。重新抓取从这条轨迹的当前呈现位置接手。恢复过程中如需响应任务尺寸变化，改由显示同步回调继续排版，不把文字或机器人缩放拉伸。
- 到达终点后清零弹簧残余速度，防止上一轮尺寸变化影响下一次收纳。
- macOS 26+ 的收纳外壳由可复用的 `CAShapeLayer` 直接填充，收纳时暂停玻璃背景，避免对整个玻璃窗口做动态离屏裁切。内容使用独立的小型圆角蒙版，恢复后回到玻璃材质。HUD 兼容路径复用同一原生蒙版，不逐帧分配新层。
- 正式入口记住手动收纳偏好。减少动态效果时，直接跟手，释放后立即到终点。右键和可访问性操作也能恢复。

## 帧诊断

独立预览提供 `⌘T`，只记录下一次回弹；`⌘P` 会先恢复待机，再在 3 秒后自动执行一次固定的斜向收纳，并把结果写入 `/tmp/dsh-notch-motion/frames-*.json`。记录包含回调间隔、图层更新耗时、窗口改尺寸次数、轮廓层分配次数及 `compositorSamples` / `renderUpdates`。恒定外壳尺寸的回弹应有合成器采样，图层更新仅发生在开始和结束；不包含会话内容。测量时不要同时读取辅助功能树或截图，以免检查动作本身打断主线程。

这些是应用的更新与提交耗时，不等于显示器最终呈现帧率。`CADisplayLink` 的目标频率也不是满帧保证；实际帧间隔仍须测量。Apple 接口依据：[NSWindow displayLink](https://developer.apple.com/documentation/appkit/nswindow/displaylink(target:selector:))。

## 解析弹簧与轮廓复用 · 2026-09-21

本次针对弹性收纳，不改机器人动作或任务状态转场。

- **解析弹簧**：用阻尼振子的闭式解直接求当前时间的位置与速度，取消逐小步积分和 50 ms 时间截断。30/60/120 Hz 附近及不规则回调描述同一条运动；主线程延迟后追上真实时间，不延长回弹。轨迹生成复用三组状态转移系数，避免每个样本重复计算三角函数。
- **同一条时间轴**：图层与状态从同一个时间原点出发；改变目标时接住当前可见位置和解析速度。合成器正在播放时，应用不重新提交每一帧。
- **轮廓复用**：在局部坐标计算连续圆角，缓存原始曲线、排序后的采样点和正文裁切路径。平移不再重新细分、重新排序；只将两个接触点插入有序轮廓，再线性求凸包。每个控制器最多保留 32 项，任务高度持续变化也会淘汰旧项。
- **尾段采样合并**：位移差不超过 0.025 pt、收纳进度差不超过 1/1024 时复用上一样本。所有图层共用同一时间表，保留精确起点和终点；不采用错误拓扑之间的路径插值。

同机 Release 基准，预热后各测 9 次，比较中位数：

| 计算内容 | 原版 | 本版 | 耗时下降 |
| --- | ---: | ---: | ---: |
| 240,000 次弹簧轴更新（预计算采样） | 2.701 ms | 1.168 ms | 56.8% |
| 4,800 帧轮廓与正文裁切生成 | 52.842 ms | 33.343 ms | 36.9% |

固定斜向回弹从 123 个候选样本保留 91 个，减少 26.0%；实际最大被合并位移差为 0.02498 pt。圆角缓存与无缓存输出完全相同；隐藏端点仍通过原始连续圆角逐点对比。

三次原生回放的开始提交耗时为 5.94 / 5.56 / 2.00 ms，均只有开始和结束两次图层更新、一次终点窗口收缩、零新建轮廓层。回调间隔 P95 为 17.42 / 17.73 / 17.43 ms；最大值为 82.41 / 90.17 / 33.30 ms，说明仍存在回调延迟。以上计算耗时和回调统计都不能证明屏幕锁满 60 fps，也不能把两个时段的提交耗时差全部归因于算法。

验证：59 项 JavaScript 测试、原生窗口几何、弹性手势回归通过；新增不同回调节奏、长暂停不慢放、双轴速度重定向、32 项缓存淘汰及逐样本误差检查。原生预览实际完成斜向收起、拉回、从选项拖走而不提交、恢复仍待决策、单击选项提交。正式 DSH 二进制未替换。

## 首版收腰与软上限 · 2026-09-23（左端形状已被下一版替代）

用户已认可原有回弹手感，本轮只增加变细和最大拉动距离。

这一版只让中间变细，左端保持原厚度。用户在试用中明确指出这不符合抓住橡胶拉伸的直觉，所以下列首版形状和对应测试记录仅作为历史，不能视为当前形状的验收。

- 单次手势前 **128 pt** 保持原来的二维跟手。之后按 `128 + 112 × tanh((距离 − 128) / 112)` 增加阻力，逐渐接近 **240 pt**；两轴共用一个径向距离，不会斜拉时先卡住某一轴。每次重新抓取从当前显示位置开始，零位移不会跳动。
- 释放速度使用同一映射的雅可比换算。手已经拉到阻力很强的区域时，回弹不会突然接收到一份更大的原始鼠标速度。短距离沿用原有速度和解析弹簧。
- 外壳的中间部分越长越细，两端和正文所占区域不缩放。自由段的最薄比例为 `1 − 0.56 × L² / (L² + 75²)`，始终大于或等于原截面的 **44%**。以 `16t²(1−t)²` 从两端原厚度平滑过渡到腰部，端点切线连续。
- 收腰直接由当前位置计算。松手、反向和中途重新抓取都沿用同一轮廓函数，不另开一个“恢复厚度”的动画。中心轴保持笔直，不增加弯曲尾巴；径向缩放为正，原轮廓顺序保持不变。
- 曲线使用自适应三次贝塞尔拟合；原来的有界轮廓缓存、合并尾段采样和 Core Animation 播放继续生效。没有新增逐帧 SwiftUI 排版。

验收通过：59 项 JavaScript 测试，原生弹性回归；新增短距离 1:1、径向最大位移、软边界导数连续、释放速度导数、长拉后重新抓取无跳变、收腰单调且不闭合、两端及正文不压扁。检查了 32 / 80 / 140 / 220 pt 横拉、斜向与向上/向下轮廓以及 60 帧回弹序列。原生预览执行长距离斜拉，收纳完成；随后读到预览已恢复正常待机。

固定轨迹保留 90 / 122 个采样，最大合并位移误差 0.02479 pt。新增形变后，当前机器上 4,800 帧轮廓生成中位数 50.33 ms，约 10.49 微秒/帧。这个数据只衡量算法计算，不是实屏帧率；本轮没有以它宣称满 60 fps。原始基准见 [本轮验证记录](verification/elastic-tension.json)。

独立预览已更新，正式 DSH 二进制未替换。此处的 240 pt 是单次手势的位移上限；正常隐藏/恢复的位置由原来的状态逻辑管理，不用此上限去裁断展开面板的宽度。

## 抓取端随拉伸变细 · 2026-09-23

修正首版只收腰、左端仍粗的错误。形变比例从右侧固定端向左侧抓取端单调增加，使用两端一、二阶导数为零的五次曲线。进入抓取端后保持最大压缩量，不再重新变粗。水平拉伸 220 pt 时，左端从 44 pt 降到约 22 pt；松手按当前位置恢复，不另设一条恢复厚度的时间轴。软上限与原来的解析回弹保持一致。

机器人、文字和局部裁切沿拉力的垂直方向使用同一压缩变换。变换围绕外壳中心，并补偿 AppKit 实际图层锚点：首轮原生回归捕获了内容层偏移，补偿后通过。SwiftUI 保留逻辑尺寸和实例，拖动时不重新排版；到达收纳或正常端点后恢复原形。

验证通过：弹性回归、原生窗口几何回归、Release 预览构建。新增检查覆盖左端实际厚度、沿长度不重新变粗、斜向内容与外壳对齐，以及原生图层边界。短、中、长距离原生预览截图确认机器人随左端一起变细；真实斜向拖动、凸起拉回、从选项拖走不误提交、恢复后单击提交均通过。用户对新形状的试用评价待确认。

一次原生回弹使用 90 个合成器采样，只有开始和结束两次图层更新、一次终点窗口收缩、零新增轮廓层。纯算法基准约 13.73 微秒/帧；运行时有并行构建负载，不能用来做严格的前后性能比较。这些记录也不等同于屏幕实际帧率。详见 [原始验证记录](verification/elastic-tip-taper.json)。
