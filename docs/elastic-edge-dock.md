# 弹性边缘收纳（候选）

向任意方向拖动 Notch，抓取点二维 1:1 跟随鼠标，整块外壳沿拉力方向伸展；松手后继承双轴速度，再回弹到边缘。收纳是将原外壳平移进屏幕，留下左侧的一小截。悬停只改变露出的多少，再拉一次恢复当前任务。

当前实现支持既有的右屏幕边缘。它不是任意位置的桌面窗口拖动，不改变会话状态或任务结果。

## 实现

- `EdgeDockModel` 保存外壳位置、尺寸、收纳进度、双轴释放速度和弹簧状态。回位时可轻微越过垂直终点；向屏幕内收纳的阻尼更大，保持残留部分可见。收纳和探出只做平移，不压缩宽高。
- `EdgePanGesture` 使用 4 pt 的二维距离判断拖动意图，不锁轴。坐标来自同一个鼠标事件并换算到屏幕，避免窗口本身变宽时反馈到拖动距离；原生文字编辑区保留选择行为。
- 手势识别器暂存主鼠标按键事件；普通单击在判定不是拖动后正常交给按钮，已识别的拖动不再把松手交给选项或审批。内容在拖动时同时禁用，避免已开始的按钮跟踪误触。
- `EdgeDockGeometry` 使用 RootView 同款的 16 pt 连续圆角。拉伸取原外壳与完整边缘接触面的单一凸包，消除“方块加细尾巴”的两条路径；离开边缘的自由端也逐渐形成圆角。轮廓沿张力展开，原生窗口和内容共用它。
- 收纳保留抓取时的原外壳高度，左侧露出 8 pt，悬停露出 14 pt。端点直接使用原始连续圆角的平移裁切。后台任务更新不会改变残留部分的形状，恢复时采用最新任务尺寸。AppKit 外层及玻璃内容层的额外圆角关闭，避免对这一小截二次裁切。
- 原有 AppKit 尺寸动画在拖拽开始时停止，避免旧展开动画继续覆盖鼠标驱动的尺寸。展开内容在收纳完成后才折叠。
- 机器人及任务视图保持同一个实例，按实际外壳尺寸排版，不随收纳缩放字形和机器人。逐帧位移和透明度交给原生图层，姿态不再逐帧发布给 SwiftUI，避免每帧重新排版。隐藏时暂停待机及时间线绘制，任务数据继续更新。
- 状态更新使用窗口的 `CADisplayLink`，目标 60 Hz。拖动时提前预留能容纳轨迹与速度余量的画布，飞行中窗口尺寸保持不变；结束后才缩回真实命中区域。
- 外壳宽高不变的回弹，以原物理求解器按 120 Hz 采样，一次提交到 Core Animation。轮廓、内容位移、透明度与局部裁切使用完全一致的采样时刻，避免主线程偶发阻塞打断回弹。重新抓取从这条轨迹的当前呈现位置接手。恢复过程中如需响应任务尺寸变化，改由显示同步回调继续排版，不把文字或机器人缩放拉伸。
- 到达终点后清零弹簧残余速度，防止上一轮尺寸变化影响下一次收纳。
- macOS 26+ 的收纳外壳由可复用的 `CAShapeLayer` 直接填充，收纳时暂停玻璃背景，避免对整个玻璃窗口做动态离屏裁切。内容使用独立的小型圆角蒙版，恢复后回到玻璃材质。HUD 兼容路径复用同一原生蒙版，不逐帧分配新层。
- 正式入口记住手动收纳偏好。减少动态效果时，直接跟手，释放后立即到终点。右键和可访问性操作也能恢复。

## 帧诊断

独立预览提供 `⌘T`，只记录下一次回弹；`⌘P` 会先恢复待机，再在 3 秒后自动执行一次固定的斜向收纳，并把结果写入 `/tmp/dsh-notch-motion/frames-*.json`。记录包含回调间隔、图层更新耗时、窗口改尺寸次数、轮廓层分配次数及 `compositorSamples` / `renderUpdates`。恒定外壳尺寸的回弹应有合成器采样，图层更新仅发生在开始和结束；不包含会话内容。测量时不要同时读取辅助功能树或截图，以免检查动作本身打断主线程。

这些是应用的更新与提交耗时，不等于显示器最终呈现帧率。`CADisplayLink` 的目标频率也不是满帧保证；实际帧间隔仍须测量。Apple 接口依据：[NSWindow displayLink](https://developer.apple.com/documentation/appkit/nswindow/displaylink(target:selector:))。

## 本轮性能复核 · 2026-09-21

- 旧版测量中，一次收纳有 29 次窗口改尺寸、73 次新建蒙版，曾出现超过一帧预算的原生提交；旧版间隔统计还受 50 ms 上限截断，不能当作精确最大卡顿值。
- 当前版本连续三次固定斜向收纳均进入合成器路径：120 个物理采样，应用只在开始和结束更新图层；松手不改窗口尺寸，仅终点收回命中区域；没有新增轮廓层。
- 三次应用回调间隔中位数都约 16.67 ms。P95 分别为 27.96 / 18.01 / 17.21 ms；仍有主线程回调延迟，最大 102.52 ms 出现在首次回调。动画在提交后由 Core Animation 播放，这些回调统计不能推导显示器实际呈现帧率，不能据此宣称锁满 60 fps。
- 原始数据：[三次帧诊断](verification/elastic-frame-timing.json)。记录了全部样本，没有只选最快一轮。
- `npm run test:edge-dock`、`npm run test:geometry`、59 项 JavaScript 测试通过。新增验证包括松手不改窗口尺寸、回弹期间固定画布、原生内容与外壳同帧对齐、当前呈现位置重新抓取、终点清零尺寸速度及轮廓复杂度约束。
- 原生预览实操通过：斜向收纳、从凸起拉回、展开问题后从选项拖走且仍保留待决策，再单击提交变为运行中。截图检查保留原形裁切；连续屏幕呈现帧率尚未取得独立采集证据。
- 本次只更新独立预览；正式 DSH.app 中的 Notch 二进制未替换。
